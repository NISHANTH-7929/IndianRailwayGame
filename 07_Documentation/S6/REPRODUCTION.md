# Reproduce S6 evidence

Run from `D:\Project\IndianRailwayGame` using PowerShell. Tools assume the installed UE 5.8.2, MSVC Build Tools and `ANDROID_HOME` paths used by this workspace. Keep the phone unlocked, authorize ADB, and leave the hotspot enabled. Use exactly one authorized endpoint for device serial `10BE1Y2EL40003J`.

1. Run `07_Documentation/S6/Tools/Test-S6.cmd`. This compiles the pure C++ suites with warnings as errors and writes all eight host result files. Existing S2–S5 tests are included.
2. Run `07_Documentation/S6/Tools/Test-Automation.ps1` for the five Unreal suites. Asset regeneration, when needed, uses `Tools/Create-S6Assets.py` through the Unreal Python commandlet. The authored `.umap`/`.uasset` files are already present.
3. Run `07_Documentation/S6/Tools/Build-S6.ps1`, then `Tools/Transfer-S6.ps1`. The transfer is resumable and verifies the complete remote SHA256 before installation. Rebuilding creates a new artifact; update evidence hashes instead of presenting old device evidence as verification of changed source.
4. Launch using `Tools/Device-S6.ps1 -Action Launch -Label <new-label>`. Run `Tools/Test-S6Device.ps1 -Label <new-label>` for controlled phone scenarios. This explicitly resets the technical fixture, changes controls, backgrounds/restarts the app and tests one corrupted checkpoint. It records taps and guards the foreground package before input.
5. Run `Tools/Test-S6Compatibility.ps1 -Label <new-label>`. It backs up both checkpoint slots, tests checksum/truncation/schema/content failures, verifies incompatible files remain unchanged, and restores the original slots in `finally`. Retain host backups if the connection interrupts restoration; reconnect and restore those exact files before continuing.
6. Run `Tools/Measure-S6.ps1 -Profile -Label <new-label>`. It captures 6,000 engine frames over a 245-second scenario. It temporarily supplies a CSV launch override and restores its previous contents/absence in `finally`. If ADB disconnects, verify and finish that restoration after reconnecting. Incomplete directories are never acceptance evidence.
7. Run `Tools/analyze_s6_csv.py <latest-CSV-from-that-run> 10 170` using the UE Python interpreter. Select the new CSV by filename/date: the Saved pull also includes historical captures. Retain both raw CSV and generated `.summary.json`. The selected window includes deliberate content pauses; it is not a claim of uninterrupted moving-train frame cost.
8. Run `Tools/Measure-S6.ps1 -Label <new-label> -Seconds 450`, then `Tools/audit_s6_residency.py <run-directory>`. This performs three explicit fixture traversals and nine forced paired chunk cycles. It also observes demand-driven single-chunk residency. The declared memory policy is in `Evidence/residency-audit-policy.json`.
9. Capture a final screenshot with `Tools/Device-S6.ps1 -Action Snapshot -Label <new-label>`, inspect it, and retain the pulled startup test JSON, logs, thermal/memory samples and telemetry. Regenerate source/artifact/evidence hashes and the acceptance mapping only when the final runs pass.

Use fresh evidence labels on retries. The finalization script intentionally expects the established `controls-final`, `compatibility-final`, `profile-final` and `sustained-final` directories and the exact tested APK hash. It fails instead of accepting another build silently. It requires the original S6 request text path as its argument to retain the exact 39 test and 30 acceptance requirement titles.

For intermittent USB, `Tools/Start-S6LocalMeasurement.ps1` starts the same bounded event schedule directly on the phone using `measure_s6_device.sh`. It runs a 245-second profile followed by a 450-second audit, checks the foreground package before every loop/action, and restores the profiling override on exit. This specific recovery runner expects the override to have been absent before testing. It refuses to start when `/data/local/tmp/ir-s6-final-measurement` already exists. Inspect `status.txt`, `FAILED`, `COMPLETE` and `runner.log` there before taking further action. After completion, pull its two phase directories into `Evidence/Device` and run `Tools/collect_s6_device_measurement.py Evidence/Device`, followed by the normal CSV/residency analyzers. Raw per-sample files are retained and every sample must parse and validate. A USB disconnect can delay collection without interrupting the on-device scenario; leaving the game foreground is still required.

Snapshots restore paused. Resume is an explicit user action. Save recovery is local, and the APK has no Android INTERNET permission; no airplane-mode or hotspot change is required. This prototype has two presentation levels and bounded proxy content. It does not measure final art or large-world capacity.

For offline inspection, run `Tools/Build-S6Inspector.cmd` after the host suites have compiled their matching object files, then `Evidence/S6Inspect.exe <checkpoint.irs>`. It rejects invalid records and exports validated logical state plus path/vehicle details as JSON without changing the record. The saved boundary and late-route examples are `Evidence/moving-checkpoint-decoded.json` and `Evidence/profile-checkpoint-decoded.json`.

If only the residency phase needs repeating, `Tools/Start-S6LocalMeasurement.ps1 -SustainedOnly` uses the separate `/data/local/tmp/ir-s6-residency-final` directory and runs a fresh 450 seconds. Preserve any interrupted run under its own evidence label; a partial run cannot be joined to another partial run to meet the duration gate.
